## Задание 1

**Какие сетевые службы в ней разрешены?**
В ходе сканирования утилитой nmap на Metasploitable были обнаружены следующие открытые сетевые службы:
- FTP (порт 2121, проброшен с 21) — сервер vsftpd 2.3.4.
- SSH (порт 2222, проброшен с 22) — сервер OpenSSH 4.7p1.
- MySQL (порт 3306) — сервер баз данных MySQL 8.0.46.
- VNC (порт 5900) — сервер удалённого доступа VNC (protocol 3.3).
- HTTP (порт 8080, проброшен с 80) — веб-сервер Apache httpd 2.2.8.

**Какие уязвимости были вами обнаружены?**
Среди найденных служб есть несколько широко известных уязвимостей, эксплойты для которых доступны на Exploit-DB:

1. **vsftpd 2.3.4 Backdoor (CVE-2011-2523)**
   - Служба: FTP (порт 21).
   - Суть: В исходный код этой версии FTP-сервера был внедрён бэкдор. Если отправить в поле логина строку со смайликом `:)`, на порту 6200 открывается root-оболочка, дающая полный контроль над системой.
   - Ссылка: https://www.exploit-db.com/exploits/17491

2. **Samba "username map script" Command Injection (CVE-2007-2447)**
   - Служба: SMB (порты 139, 445).
   - Суть: Уязвимость позволяет удалённо выполнить произвольные команды через специально сформированное имя пользователя. Эксплуатация приводит к получению прав суперпользователя (root).
   - Ссылка: https://www.exploit-db.com/exploits/16320

3. **UnrealIRCd 3.2.8.1 Backdoor (CVE-2010-2075)**
   - Служба: IRC (порт 6667).
   - Суть: В официальный архив с этой версией IRC-сервера был внедрён троян. Он позволяет злоумышленнику отправлять команды, которые выполняются на сервере с правами администратора.
   - Ссылка: https://www.exploit-db.com/exploits/13853

## Задание 2

Сканирование проводилось утилитой nmap с записью трафика в Wireshark (интерфейс Loopback, так как использовался проброс портов).

**1. SYN-сканирование (-sS)**
![SYN-сканирование](https://github.com/ice017-git/Vulnerabilities_and_attacks_on_information_systems/blob/main/img/SYN.png)

В трафике видно, что nmap отправляет пакет с флагом SYN, получает SYN/ACK (порт открыт) и сразу отправляет RST, обрывая соединение.

**2. FIN-сканирование (-sF)**
![FIN-сканирование](https://github.com/ice017-git/Vulnerabilities_and_attacks_on_information_systems/blob/main/img/FIN.png)

В трафике видно, что nmap отправляет пакет с флагом FIN. Открытые порты на него не отвечают (поэтому состояние open|filtered).

**3. Xmas-сканирование (-sX)**
![Xmas-сканирование](https://github.com/ice017-git/Vulnerabilities_and_attacks_on_information_systems/blob/main/img/Xmas.png)

В трафике видно, что nmap отправляет пакет с флагами FIN, PSH и URG. Открытые порты, как и в случае с FIN, не отвечают.

**4. UDP-сканирование (-sU)**
![UDP-сканирование](https://github.com/ice017-git/Vulnerabilities_and_attacks_on_information_systems/blob/main/img/UDP.png)

В трафике видно, что nmap отправляет UDP-пакет. Так как на этих портах нет UDP-служб, сервер отвечает ICMP-сообщением "Port Unreachable" (порт закрыт).

**Чем отличаются эти режимы с точки зрения сетевого трафика?**
- SYN: Отправляется флаг SYN, ожидается ответ SYN/ACK (открыт) или RST (закрыт). Это активное сканирование, которое легко обнаружить.
- FIN и Xmas: Отправляются нестандартные комбинации флагов (FIN или FIN+PSH+URG). Открытые порты их игнорируют, а закрытые отвечают RST. Это «стелс»-методы, так как они не создают полных сессий.
- UDP: Отправляются UDP-пакеты, и результат зависит от ответа приложения или ICMP-ошибки. Это медленный метод, так как нет подтверждений.


**Как отвечает сервер?**
Сервер реагирует в соответствии со своей сетевой логикой: на SYN отвечает SYN/ACK (если порт открыт), на FIN/Xmas не отвечает (если порт открыт) или шлёт RST (если закрыт), на UDP либо отдаёт данные службы, либо присылает ICMP-ошибку.
